# Nine Lives Audio — 优化与中文本地化说明

> 本文档记录本轮的优化项、本地化架构、以及如何自检与打包。
> 所有结论都可用 `python tools/verify.py` 复现，无需 Windows 环境。

## 1. 本地化（English / 简体中文）

### 1.1 设计

| 组件 | 作用 |
| --- | --- |
| `Models/AppSettings.Language` | 持久化偏好：`system` \| `en-US` \| `zh-CN`，默认 `system`（跟随系统） |
| `Services/ILocalizationService` | `GetString` / `Format` / `SetLanguageAsync` / `RefreshFromSettings` / `CurrentLanguage` / `IsChinese` / `LanguageChanged` |
| `Services/LocalizationService` | 代码式双语资源（245 个 key，中英一一对应），无 `.resw`/PRI，打包零风险 |
| `Helpers/AppLanguage` | 环境语言标志，供 `TimeFormatHelper`、`AudioBook` 等无 DI 的静态/模型代码使用 |
| `Helpers/Loc` | XAML 附着属性 `loc:Loc.Text/Content/Header/Placeholder`，语言切换后原地刷新 |

切换路径：设置页 → 外观 → 语言 → `SettingsViewModel.ApplyLanguageCommand` →
`SetLanguageAsync`（写设置 + 置 `AppLanguage`）→ `LanguageChanged` →
`Loc.ReapplyAll()` ＋ 各页面 `ApplyLocalization()`，**无需重启**。

### 1.2 用法

```csharp
// C#
Title = _localization.GetString("LibraryTitle");
Message = _localization.Format("DaysAgo", 3);
```

```xml
<!-- XAML：不需要代码后台 -->
<Button loc:Loc.Content="SaveSettings"/>
<ToggleSwitch loc:Loc.Header="HideFinished"/>
<TextBox loc:Loc.Placeholder="EnterUsername"/>
```

### 1.3 为什么发布目录里有很多语言文件夹

应用自身的界面语言**只有两套**（`en-US` / `zh-CN`），设置页里也只有
「Follow system / English / 简体中文」三项。发布目录（`binpublish`）里那一堆
`cs/ de/ es/ fr/ it/ ja/ ko/ pl/ pt-BR/ ru/ tr/ ...` 文件夹**不是本应用的翻译**，
而是 NuGet 依赖（Microsoft.WindowsAppSDK、CommunityToolkit、.NET 基础库等）
自带的**卫星资源程序集（satellite assemblies）**，每个语言一个子目录。

现在 `NineLivesAudio.csproj` 里加了：

```xml
<SatelliteResourceLanguages>en;zh-Hans</SatelliteResourceLanguages>
```

即只保留英文 + 简体中文，其余语言目录在 `dotnet publish` 时被裁掉（包体更小，
目录也清爽）。这不影响应用自己的中英文切换——那套资源是代码里的字典，与这些
文件夹无关。

### 1.4 规则（由自检脚本强制）

1. 新增 key 必须**同时**写入 `en-US` 与 `zh-CN` 两个字典，否则 `verify.py` 失败。
2. `Format` 模板里的 `{0}`… 数量必须与调用点实参数量一致。
3. `loc:Loc.*` 只能用在支持对应属性的控件上（`TextBlock->Text`、`Button->Content`、
   `ToggleSwitch/ComboBox/TextBox/PasswordBox->Header`、`TextBox/PasswordBox/ComboBox->Placeholder`）。
4. 使用 `loc:` 的文件必须声明 `xmlns:loc="using:NineLivesAudio.Helpers"`。

## 3. 自检（`tools/verify.py`）

```bash
python tools/verify.py
```

15 组检查，全部离线、跨平台：

1. 所有 `.xaml` / `.csproj` 是良构 XML
2. C# 花括号/圆括号/方括号配平（忽略字符串与注释）
3. 单个 XAML 内无重复 `x:Name`
4. XAML 引用的事件处理器在代码后台存在
5. 控件名/成员交叉校验
6. 本地化 key：中英集合一致，且代码/XAML 引用的 key 都存在
7. `Format` 实参数量与模板占位符一致
8. `loc:Loc.*` 与控件类型匹配
9. DI 图：所有构造函数依赖都已在 `App.xaml.cs` 注册（且不会依赖「注册为接口」的具体类）
10. 应用 XAML 引用的 `StaticResource/ThemeResource` key 都有定义
11. 打包一致性：资源文件、发布配置、TFM 三处一致（csproj/脚本/README）、`installer.iss` 版本与输出目录一致、发布配置的 RID 必须在 `RuntimeIdentifiers` 内
12. XAML 命名空间声明（`xmlns:loc` 必须存在，`using:NineLivesAudio.*` 必须指向真实命名空间）
13. 缺失 `using`：使用 `KeyboardAccelerator` / `MenuFlyout*` / `ContentDialog` / `PasswordVault` 等类型时必须引入对应命名空间（这条规则是本次手工踩到后补的）
14. 「服务器连上但书库为空」回归防护：API 层必须识别 HTTP 401（不能把失败伪装成空集合）、`SyncLibrariesAsync` 必须在空结果时保留本地缓存、书库页必须响应连接恢复事件（见 §7）
15. `DataTemplate` 内的 `x:Name` 不是页面字段：代码后台一旦直接引用就是编译错误 CS0103（这条由 CI 真实编译暴露后补上，见 §8）

当前状态：**✓ all checks passed**（83 个 C# 文件 / 13 个 XAML / 256 个本地化 key）。

## 6. 跳过开头 / 跳过结尾（全局设置）

> 上一版误做成「跳到本章开头 / 本章结尾」两个按钮，已按需求**移除**（控制行两个按钮 +
> 章节菜单里的「跳到开头 / 跳到结尾」入口 + `Ctrl+←/→` 快捷键一并删除）。
> 现在只有「设置 → 播放」里的两个全局选项。

| 设置项 | 含义 | 默认 | 范围 |
| --- | --- | --- | --- |
| 跳过开头 | 书籍开始播放时自动跳过前 N 秒（每次加载书籍生效一次） | 0（关闭） | 0–600 秒 |
| 跳过结尾 | 剩余不足 N 秒时自动跳到下一章；已是最后一章则直接标记为已听完 | 0（关闭） | 0–600 秒 |

实现要点：

- 配置存在 `AppSettings.SkipIntroSeconds` / `SkipOutroSeconds`，与其它设置一起写入 `settings.json`；
  设置页用 `NumberBox`（步进 15 秒），`NumberBox` 清空时返回 `NaN`，会统一夹到 `0..600`。
- 跳过开头：`AudioPlaybackService.PlayAsync()` → `ApplyIntroSkipAsync()`；
  **只在当前位置仍处于开头区间内**才跳，续播不会往回跳；书太短（`时长 ≤ 2×跳过值`）时自动忽略。
- 跳过结尾：500ms 的位置轮询里判断 `剩余 ≤ N`，用 `_outroSkipInProgress` 防重入；
  找到下一个「开始时间 > 当前位置」的章节就跳过去，没有则
  `FlushPlaybackProgressAsync(..., isFinished: true)` 并关闭会话。
- 两者都读的是同一个 `ISettingsService.Settings` 实例，设置页保存后**无需重启**即刻生效。
- 播放页仍保留「上一章 / 下一章」（`Ctrl+Shift+←/→`）与章节列表（点击即跳到该章开头）。

相关文案键：`SkipIntro`、`SkipIntroHint`、`SkipOutro`、`SkipOutroHint`（中英各一套）。

## 7. 「服务器连上了，但书是空的」（已修复）

### 7.1 现象

顶部连接状态是「已连接」，书库却一片空白，没有任何报错；重启或手动下拉有时又能恢复。

### 7.2 根因

`AudioBookshelfApiService` 里所有请求都是同一个形状：

```csharp
try { ... } catch (Exception) { return new List<...>(); }   // ← 把失败伪装成"空"
```

于是网络抖动、超时、JSON 解析失败、token 过期（401）全都被渲染成「服务器说没有书」。后续链路被这个假象带偏：

1. `SyncService.SyncLibrariesAsync` 拿到空库 → `SaveLibrariesAsync(空)` → `foreach` 一次都不执行 → 不会保存任何书 → 界面自然空的；
2. `LibraryViewModel.LoadAudioBooksAsync` 里的「离线兜底」（`ShowDownloadedOnly = true` + 提示）只在**抛异常**时触发，而空列表不抛异常 → 兜底永不执行 → 用户既看不到书，也看不到提示。

5 个具体诱因：

| # | 诱因 | 后果 |
| --- | --- | --- |
| 1 | token 过期返回 401，`EnsureAuthenticated` 只在「无 token」时抛 | 静默空库 |
| 2 | 启动时 3 秒 token 校验超时（慢网络） | 后台同步根本没启动 |
| 3 | 分页终止条件用 `total`，服务器返回 `total = 0` 时 | 只取到前 100 本 |
| 4 | 启动同步与书库页同步并发、无合并 | 重复请求、互相覆盖 |
| 5 | `SelectedLibrary == null` 时直接 `return` | 空列表且无提示 |

### 7.3 修复

- **API 层区分"成功但空"与"请求失败"**：新增 `LastRequestUnauthorized`（HTTP 401 时置位，直到下一次请求成功才清除）与 `InvalidateSession()`；`GetLibrariesAsync` / `GetLibraryItemsAsync` 对 401 单独处理，不再静默吞掉。
- **空结果不再覆盖缓存**：`SyncLibrariesAsync` 在「服务器返回 0 个库」或「某个库返回 0 本书」时打警告并保留本地数据。
- **401 有明确提示**：书库页检测到会话失效 → 清掉内存 token、状态切换为「未连接」、弹一次「登录已过期，请在设置中重新登录」。
- **离线兜底可自动恢复**：兜底只显示已下载书籍，并记录「是程序自己开的」；服务器恢复后自动关掉该筛选并提示「服务器已恢复连接，已显示全部书籍」，不会覆盖用户手动打开的同名筛选。
- **连接恢复自动刷新**：书库页订阅 `ConnectivityChangedMessage`，服务器重新可达时用 `DispatcherQueue` 回主线程重新拉取。
- **分页终止条件改为「返回不足一页即结束」**，同时保留 `total > 0` 的校验，并加 200 页上限保护。
- **同步合并**：`_librariesLock` 让并发的同步排队复用同一次结果，启动同步与页面加载不再重复下载。
- **启动不再依赖 3 秒校验**：后台同步服务总是启动（`SyncNowAsync` 自己会在未登录时跳过），校验超时从 3s 放宽到 8s。
- **空库不再静默**：`SelectedLibrary == null` 时自动选第一个库；真的没有库时刷新空状态文案。

### 7.4 自检

`tools/verify.py` 新增第 14 组检查，锁定以上不变量（已用「故意改坏」的方式验证会报错）：

```
✗ [silent-fail] AudioBookshelfApiService: ... GetLibrariesAsync() swallows HTTP 401
✗ [silent-fail] SyncService.SyncLibrariesAsync must bail out when the server returns no libraries
✗ [silent-fail] LibraryViewModel must reload when the server becomes reachable again
```

## 9. 章节跳转与时长显示（本轮修复）

### 9.1 现象

1. 播放页打开「章节」模式时，**播到下一章的那一瞬间**，右侧剩余时间/时间刻度会突然变成**整本书**的长度；
2. 有些多文件（一章一个 mp3）的书，时长显示/跳转位置看着不对。

### 9.2 原因

| # | 原因 | 说明 |
| --- | --- | --- |
| 1 | 时间文字被两套代码同时写 | `PlaybackService_PositionChanged` 是章节维度，`UpdateControlsUI()` 却无条件写 `ViewModel.CurrentPositionText/RemainingTimeText`（**全书维度**）。切章会触发 `TrackChanged`/状态变化 → `UpdateAllUI()` → 把章节刻度覆盖成全书刻度 |
| 2 | 章节不覆盖整条时间轴时章节上下文丢失 | 章间有间隙（片头片尾未被章节覆盖）时 `FindChapterForPosition` 返回 `-1` → `CurrentChapter == null` → 章节模式无处可画，回落到全书 |
| 3 | 每文件时长来自服务器元数据，可能缺失 | 累加表出现 0/重复项时：总时长变 0、`DetermineStartingTrack` 误判到最后一个文件、章节偏移全错 |

### 9.3 修复

- **单一渲染入口** `RefreshProgressDisplay(TimeSpan?)`：章节模式 → 全章节维度；否则 → 全书维度；章节未知时也回落全书，**不再留旧值**。`UpdateControlsUI()` 改为调用它（拖拽时跳过）。
- **章节间隙**：二分查找失败时回落到「开始时间 ≤ 当前位置的最后一个章节」，章节上下文不再丢。
- **时长自愈**：`ReconcileTrackDuration(trackIndex, 解码器实测时长)`——每打开一个文件，就用解码器给出的真实长度校正累加表（差值 ≥ 1s 才动），总时长与所有章节偏移同步修正。
- **元数据缺失兜底**：累加表不是严格递增时，`RebuildDurationsFromFiles()` 用 `AudioFileReader` 直接读每个文件的头信息重建。
- **跨文件跳转不再有杂音**：`SeekAsync` 先按 `autoPlay: false` 打开目标文件，落位后再播放（之前会先从 0 秒响一下）。

### 9.4 「跳转是不是按章节」的核对结论

**是**。章节的 `Start/End` 是**全书秒数**，跳转链路：

```
点击章节 / 上一章 / 下一章
  → IAudioPlaybackService.SeekToChapterAsync(i)
  → SeekAsync(TimeSpan.FromSeconds(chapters[i].Start))     // 全书时间轴
  → SeekAsync: 用累加表算出「第几个文件 + 文件内偏移」
  → 播放器落位，并直接设置 _currentChapterIndex
```

数值核对（一份 3 文件 / 6 章节、总长 2:30:00 的书）：

| 目标 | 期望 | 计算结果 |
| --- | --- | --- |
| 第 3 章（1:00:00，正好是第 2 个文件开头） | 文件 2，偏移 0:00:00 | ✅ 文件 2 / 0:00:00，回读位置 1:00:00 |
| 第 4 章（1:30:00，第 2 个文件内 30 分处） | 文件 2，偏移 0:30:00 | ✅ 文件 2 / 0:30:00，回读位置 1:30:00 |
| 第 5 章（2:00:00，单文件书） | 直接 seek 2:00:00 | ✅ |
| 元数据里每文件时长都是 0 | 修复后总时长正确 | ✅ 2:29:58（实测之和） |
